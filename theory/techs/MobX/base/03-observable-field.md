# An observable field

Детализация п. 3 уровня «base», MobX. Оглавление: [index.md](./index.md).

Конспект: сначала о чём речь и зачем это нужно на этом уровне, потом устройство, пример, ловушка и короткая формулировка, с которой тему можно закрыть.

#### О чём речь

Единица состояния — поле помеченного объекта: `order.amount`. Реакция обновляется, когда это поле присваивают, и только если реакция читает само поле. Скопируйте число в локальную переменную, и реакция навсегда останется с копией. Эта ошибка появляется раньше массивов, вложенных объектов и React. Поле наблюдаемо, потому что объект пометил `makeAutoObservable` (этот уровень, п. 2).

---

#### Модель

Поле — это одна ячейка ввода из этот уровень, п. 1. Оно живёт на объекте. Чтение `order.amount` во время реакции связывает эту реакцию с этой ячейкой. Присваивание `order.amount = 4` — это правка. Реакции, которые читали эту ячейку, запускаются снова уже с `4`.

Число `4` само по себе не наблюдаемо. Наблюдаемо поле, которое его держит. У двух заказов свои `amount`.

---

#### Чтение поля

Чтение возвращает текущее значение. Если в этот момент выполняется derivation или reaction, чтение ещё и записывает, что поле использовали. Чтение из обычного кода, вне всякой реакции, возвращает значение и ничего не записывает. Эта строка уже закончилась, поэтому поздние присваивания к ней не возвращаются. Какие чтения внутри работающей функции входят в список, — этот уровень, п. 11. Здесь правило уже: реакция должна читать поле, а не копию, снятую раньше.

#### Присваивание поля

И `order.amount = 4`, и `order.amount += 1` присваивают поле. Реакции, которые читают `order.amount`, на следующем запуске видят новое число. Присваивайте из метода объекта. Голое присваивание поле всё равно меняет, и в разработке MobX предупреждает, если за полем уже кто-то наблюдает (этот уровень, п. 7). Несколько присваиваний в одном методе — одно уведомление (этот уровень, п. 6).

#### У каждого поля своя ячейка

`price` и `amount` разделены. Реакция, которая читает оба, запускается, когда присваивают любое из них. Реакция, которая читает только `amount`, не запускается, когда присваивают только `price`.

---

#### Пример

```javascript
import { makeAutoObservable, autorun } from "mobx"

const order = makeAutoObservable({
    amount: 1,
    setAmount(next) {
        this.amount = next
    }
})

const log = []
autorun(() => {
    log.push(order.amount)
})
order.setAmount(4)
// log равен [1, 4]

const lookedUp = order.amount
// lookedUp равен 4
order.setAmount(9)
// lookedUp по-прежнему 4
// log равен [1, 4, 9]
```

Реакция прочитала `order.amount`, запомнила `1`, а после `setAmount(4)` запомнила `4`. `lookedUp` хранит число `4` с момента копирования. Реакция каждый раз читает поле, поэтому лог получает `9`, а `lookedUp` нет.

---

#### Ловушка

Реакция, замкнутая на скопированное число, выглядит как подписка и никогда не обновляется.

```javascript
import { makeAutoObservable, autorun } from "mobx"

const order = makeAutoObservable({
    amount: 1,
    setAmount(next) {
        this.amount = next
    }
})

const snapshot = order.amount
const log = []
autorun(() => {
    log.push(snapshot)
})
order.setAmount(4)
// log равен [1]
// order.amount равен 4
```

`snapshot` — это число `1`. Реакция ни разу не читает `order.amount`. Присваивание обновляет поле, а лог остаётся `[1]`. Читайте `order.amount` внутри `autorun`.

---

#### Сводка

Читайте и пишите поле на объекте. Локальный `const` держит число одного момента. В обычной работе функция реакции каждый раз называет `order.amount`, когда ей нужно значение.

#### Граница инструмента

Это MobX на поле, которое пометил `makeAutoObservable`. Локальный `const` или `let` остаётся обычной переменной JavaScript.

#### Чем закрыть тему

Направьте `autorun` на `order.amount`, присвойте новое число из метода и проверьте, что лог заканчивается этим числом. Скопируйте поле в `const` до второго `autorun`, присвойте снова и проверьте, что второй лог не растёт.

Уровень base по оглавлению закончен.
