# Changing an observed field outside an action

Детализация п. 7 уровня «base», MobX. Оглавление: [index.md](./index.md).

Конспект: сначала о чём речь и зачем это нужно на этом уровне, потом устройство, пример, ловушка и короткая формулировка, с которой тему можно закрыть.

#### О чём речь

Когда реакция уже читает поле, следующее изменение принадлежит action (этот уровень, п. 5). В разработке голое `order.amount = 3` печатает предупреждение. Присваивание всё равно происходит. Прочитайте предупреждение как выброшенную ошибку, и будете искать запись, которая не сорвалась. В поле лежит `3`. Другие режимы строгости — advanced, п. 53.

---

#### Модель

Пока ячейку никто не читает, подготовка может править её тихо. Когда диаграмма уже пользуется ячейкой, MobX хочет, чтобы следующая правка была action. Голое присваивание диаграмму всё равно обновляет. В разработке оно ещё печатает предупреждение.

«Уже наблюдают» значит: derivation или reaction прочитали поле и всё ещё активны. Пока этого не случилось, код конструктора может присваивать поле после `makeAutoObservable`, и MobX молчит.

---

#### Запись остаётся

В разработке консоль показывает предупреждение такого вида:

`[MobX] Since strict-mode is enabled, changing (observed) observable values without using an action is not allowed. Tried to modify: Order@1.amount`

Следующая строка всё равно выполняется. `order.amount` равен присвоенному значению. Реакции, которые его читают, запускаются и видят это значение. Исключения нет, поэтому `try/catch` вокруг присваивания не срабатывает. Это проверка разработки. Сборки production — expert, п. 15.

#### Подготовка идёт до первого наблюдателя

Создайте объект, присвойте `amount`, потом запустите `autorun`. Эти ранние присваивания не предупреждают. Обычное место — конструктор: пометить объект, задать начальные значения, вернуться. Предупреждение начинается с первого голого присваивания после того, как реакция уже наблюдает это поле.

#### Каждое голое присваивание уведомляет отдельно

Два голых присваивания — не один action, поэтому это не один общий запуск (этот уровень, п. 6). Каждое присваивание обновляет реакции до следующей строки. Предупреждение — это отсутствующий action. Лишние запуски — то же правило группировки. Положите оба присваивания в один метод.

---

#### Пример

```javascript
import { makeAutoObservable, autorun } from "mobx"

const order = makeAutoObservable({
    amount: 1,
    add(extra) {
        this.amount += extra
    }
})

const log = []
autorun(() => {
    log.push(order.amount)
})
// log равен [1]

order.add(2)
// log равен [1, 3]

order.amount = 9
// консоль разработки: предупреждение strict-mode про order.amount
// log равен [1, 3, 9]
// order.amount равен 9
```

`add` меняет наблюдаемое поле из метода, поэтому предупреждения нет. Голое присваивание предупреждает и всё равно сохраняет `9`. Реакция тоже сохраняет `9`. Присваивание, сделанное до появления этого `autorun`, не предупреждает: поле ещё никто не наблюдает.

---

#### Ловушка

Если принять предупреждение за отклонённую запись, начнёте искать сбой, которого не было.

```javascript
import { makeAutoObservable, autorun } from "mobx"

const order = makeAutoObservable({ amount: 0 })
autorun(() => {
    void order.amount
})

order.amount = 4
// консоль разработки предупреждает
// order.amount равен 4
```

Код после этой строки видит `4`. Реакция, которая печатает `order.amount`, печатает `4`. Уберите предупреждение, присваивая внутри метода: `order.setAmount(4)`. Второе присваивание снова предупредит и снова перезапишет поле.

---

#### Сводка

Когда реакция уже читает поле, меняйте его из метода. Голое присваивание в разработке печатает предупреждение strict-mode и оставляет новое значение на месте. Присваивания до первого наблюдателя не предупреждают.

#### Граница инструмента

Предупреждение — это MobX во время разработки. JavaScript присваивание всё равно выполняет. TypeScript его не сообщает.

#### Чем закрыть тему

Наблюдайте поле, присвойте его вне всякого метода и проверьте и предупреждение разработки, и новое значение в поле. Перенесите присваивание в метод, вызовите его и проверьте, что значение обновилось без предупреждения.

Уровень base по оглавлению закончен.
