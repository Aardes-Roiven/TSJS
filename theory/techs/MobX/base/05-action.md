# An action

Детализация п. 5 уровня «base», MobX. Оглавление: [index.md](./index.md).

Конспект: сначала о чём речь и зачем это нужно на этом уровне, потом устройство, пример, ловушка и короткая формулировка, с которой тему можно закрыть.

#### О чём речь

Action — это метод, которым меняют наблюдаемые поля. `order.add(1)` принимает аргументы, возвращает значение и в теле присваивает `this`. По этому методу читатель видит, как двигается `amount`. Разбросайте присваивания по случайным функциям, и у следующего изменения не будет места. Несколько присваиваний внутри одного вызова становятся одной реакцией в этот уровень, п. 6. Голое присваивание снаружи в разработке даёт предупреждение: этот уровень, п. 7.

---

#### Модель

На электронной таблице из этот уровень, п. 1 action — это один жест, которым в ячейки ввода вписывают новые числа. Формула и диаграмма обновляются после жеста. Сами они жестом не зовут. Action не подписывается и не запускается, когда меняется поле. Его вызываете вы.

`makeAutoObservable` даёт методам эту роль (этот уровень, п. 2). Метод пишут как обычно. Если метод уже принадлежит объекту, место вызова остаётся `order.add(1)`.

---

#### Метод присваивает поля

Тело присваивает наблюдаемые поля и может вызывать другие методы того же объекта. Оно может принимать аргументы и возвращать значение, например новый `amount`. Этот возврат — обычный возврат JavaScript, не подписка.

Метод, который только читает поля и возвращает ответ, можно вызывать из `autorun`. Эти чтения принадлежат `autorun`. Метод, чья работа — менять состояние, вызывают из события. Как MobX отличает эти два вызова, — expert, п. 5.

#### Вызов не повторяется

После возврата `order.add(1)` поля держат новые значения. Если поздняя строка присвоит `amount` другим путём, `add` сам не запустится. Реакции перезапускаются. Action выполняется, когда его вызвали.

`order.add(1)` на время вызова ставит `this` в `order`. Если снять функцию с объекта и вызвать её одну, `this` пропадает. Это этот уровень, п. 8.

---

#### Пример

```javascript
import { makeAutoObservable, autorun } from "mobx"

const order = makeAutoObservable({
    amount: 1,
    add(extra) {
        this.amount += extra
        return this.amount
    }
})

const log = []
autorun(() => {
    log.push(order.amount)
})

const next = order.add(2)
// next равен 3
// log равен [1, 3]

order.amount = 10
// log равен [1, 3, 10]
// add не вызывали
```

Вызывающий передаёт `2` и получает `3`. Реакция читает поле, и лог получает `3`. Позднее голое присваивание меняет поле, и реакция запускается снова. `add` простаивает, потому что его никто не вызвал. Предупреждение разработки для этого присваивания — этот уровень, п. 7. Настоящие изменения идут через `order.add`.

---

#### Ловушка

Метод не поддерживает правило истинным после поздних правок. Он выполнился, когда его вызвали.

```javascript
import { makeAutoObservable } from "mobx"

const order = makeAutoObservable({
    amount: 1,
    double() {
        this.amount = this.amount * 2
    }
})

order.double()
// order.amount равен 2

order.amount = 5
// order.amount равен 5
```

`double` записал `2` и закончился. Позднее присваивание записывает `5`. `double` никто не вызывает, поэтому amount не становится `10`. Если произведение должно оставаться текущим при каждой смене `amount`, напишите `get doubled()` и читайте его. Если оно должно меняться только по просьбе пользователя, вызывайте `double()` в этот момент.

---

#### Сводка

Изменения полей кладите в методы и вызывайте эти методы. Геттер — когда значение должно оставаться свежим само. `autorun` — когда побочный эффект должен выполняться снова. Action — один вызов на один жест.

#### Граница инструмента

Action — это функция JavaScript. У MobX нет отдельного синтаксиса вызова. Аргументы и возврат ведут себя как у любого другого метода.

#### Чем закрыть тему

Напишите метод, который меняет поле и возвращает новое значение. Вызовите его и проверьте и возврат, и лог `autorun`. Измените поле, не вызывая метод, и проверьте, что метод больше не выполнился.

Уровень base по оглавлению закончен.
