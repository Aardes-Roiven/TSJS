# A computed must not write state or perform a side effect

Детализация п. 21 уровня «base», MobX. Оглавление: [index.md](./index.md).

Конспект: сначала о чём речь и зачем это нужно на этом уровне, потом устройство, пример, ловушка и короткая формулировка, с которой тему можно закрыть.

#### О чём речь

Геттер — это формула. Она возвращает значение и чужие ячейки не правит. Запись в наблюдаемое поле из геттера в разработке печатает предупреждение, и запись всё равно происходит. Другая реакция видит эту правку посреди чужого пересчёта. Лог, `fetch` или присваивание флага внутри `get total()` срабатывают не тогда, когда об этом просят, а когда MobX решает заново посчитать формулу, и пропускаются, когда результат взят из кэша (этот уровень, п. 4). Флаг, который следует из полей, делают вторым геттером. Побочный эффект кладут в `autorun` (этот уровень, п. 9).

---

#### Модель

Формула из этот уровень, п. 1 читает ячейки ввода и показывает число. Жест, которым ячейки правят, — это action (этот уровень, п. 5). Формула жестом не пользуется. Пока её читает реакция, MobX выполняет тело, только если вход изменился, и будит читателей, только если результат другой.

Запись в уже наблюдаемое поле из этого тела — попытка жеста во время формулы. В разработке консоль показывает предупреждение того же вида, что и голое присваивание (этот уровень, п. 7): strict-mode, имя поля, которое формула попыталась изменить. Исключения нет. Поле меняется. Реакция, которая это поле читает, получает лишний проход.

`console.log` внутри геттера MobX не перехватывает. Строка появляется, когда тело действительно выполнилось, и не появляется, когда результат отдан из кэша. По логу нельзя судить, что значение «обновилось»: обновление экрана и выполнение тела — разные события (этот уровень, п. 4).

---

#### Второй геттер вместо записанного флага

Флаг, который считается из тех же полей, что и сумма, — тоже формула. `get charged() { return this.price * this.amount > 0 }` ничего не присваивает. Реакция, которая читает `order.charged`, запускается, когда меняется этот boolean. Отдельного поля `charged` нет, записать его некому, предупреждению не на что сработать.

Запись `this.charged = ...` внутри `get total()` делает два дела в одном теле: возвращает сумму и правит другую ячейку. Читатель суммы получает число. Читатель флага получает проход, о котором формула суммы не объявляла.

#### Эффект живёт в реакции

Строка лога, запрос и запись на экран зависят от того, что формула уже посчитана, и выполняются своей реакцией. `autorun(() => { log.push(order.total) })` читает геттер и делает эффект снаружи него. Тело геттера возвращает число и на этом заканчивается. Кэш может пропустить тело. Реакция при том же результате тоже не повторит эффект. Оба пропуска здесь совпадают с правилом формулы, а не с пропущенным логом внутри неё.

---

#### Пример

```javascript
import { makeAutoObservable, autorun } from "mobx"

const order = makeAutoObservable({
    price: 2,
    amount: 1,
    get total() {
        return this.price * this.amount
    },
    get charged() {
        return this.total > 0
    }
})

const flags = []
autorun(() => {
    flags.push(order.charged)
})
const totals = []
autorun(() => {
    totals.push(order.total)
})
// flags равен [true]
// totals равен [2]
```

Оба геттера только читают поля и возвращают значение. Предупреждения нет. `charged` следует из `total`, `total` следует из `price` и `amount`. Присваивать флаг незачем: его уже можно прочитать.

---

#### Ловушка

Геттер суммы заодно пишет наблюдаемый флаг. Предупреждение появляется, когда флаг уже кто-то читает, и оба лога всё равно растут.

```javascript
import { makeAutoObservable, autorun } from "mobx"

const order = makeAutoObservable({
    price: 2,
    amount: 1,
    charged: false,
    get total() {
        this.charged = this.price * this.amount > 0
        return this.price * this.amount
    }
})

const flags = []
autorun(() => {
    flags.push(order.charged)
})
// flags равен [false]

const totals = []
autorun(() => {
    totals.push(order.total)
})
// в разработке консоль предупреждает про изменение charged
// totals равен [2]
// flags равен [false, true]
```

Первая реакция уже наблюдает `charged`. Второе чтение `total` выполняет геттер, геттер присваивает `charged`, предупреждение называет это поле. Сумма в лог попадает, и флаг тоже меняется на `true`. Формула поправила чужую ячейку. Уберите поле `charged` и верните boolean из его геттера, как в примере выше. Повторный проход за флагом тогда даёт сам геттер, без записи.

---

#### Сводка

| Тело геттера | Что видит читатель |
|---|---|
| Возвращает число или boolean из других полей | Результат формулы, без предупреждения |
| Присваивает наблюдаемое поле | Предупреждение в разработке, поле меняется, чужая реакция получает проход |
| Пишет в лог или вызывает запрос | Эффект случается только на тех проходах, где тело выполнилось, и молчит, когда ответ взят из кэша |

Геттер возвращает значение. Всё, что должно случиться из-за этого значения, делает реакция, которая его прочитала.

#### Граница инструмента

Предупреждение печатает MobX в разработке. В production этой проверки нет, а присваивание из геттера остаётся (expert, п. 15). Кэш тела — тоже MobX. JavaScript геттер сам не отличает формулу от эффекта.

#### Чем закрыть тему

Сделайте два геттера: сумма и флаг от суммы. Прочитайте оба из двух `autorun` и проверьте, что предупреждения нет, а в логах лежат посчитанные значения. Перенесите присваивание флага внутрь геттера суммы, сначала подпишитесь на флаг, потом прочитайте сумму и проверьте, что консоль предупредила, сумма записалась, и лог флага получил лишнее значение.

Уровень base по оглавлению закончен.
