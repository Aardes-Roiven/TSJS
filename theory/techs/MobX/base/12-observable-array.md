# An observable array: index assignment, length, and push

Детализация п. 12 уровня «base», MobX. Оглавление: [index.md](./index.md).

Конспект: сначала о чём речь и зачем это нужно на этом уровне, потом устройство, пример, ловушка и короткая формулировка, с которой тему можно закрыть.

#### О чём речь

Наблюдаемый массив — это список в одной ячейке, а не отдельная подписка на `push`, на индекс и на `length`. Присваивание индекса, смена `length` и `push` будят одну и ту же диаграмму: ту, которая за этот проход заглянула в слот, в длину или прошлась по списку. Реакция, которая только подержала ссылку на массив и внутрь не заглянула, от `push` не просыпается. Первая отрисовка списка тогда либо молчит после добавления, либо кажется сломанной, хотя элемент в массиве уже лежит.

---

#### Модель

Поле `items` — ячейка, в которой лежит список. Заглядывание в слот, чтение `length` и проход `map`, `forEach` или `join` смотрят на сам список. `push`, `pop`, `shift`, `unshift`, `splice`, присваивание `items[i]` и присваивание `items.length` меняют этот список. Любое такое изменение будит реакции, которые список смотрели.

Замена ячейки целиком, `this.items = ["c"]`, — другая стрелка. Её видит тот, кто читал поле `items`. Подробно замена и правка разделены в этот уровень, п. 13.

`makeAutoObservable` превращает массив из литерала объекта в такой список (этот уровень, п. 2). Методы массива вызывают из action, как и остальные присваивания (этот уровень, п. 5).

---

#### Присваивание индекса

`this.items[0] = "z"` записывает слот. Если в слоте уже лежит другое значение, список меняется, и реакции, которые его смотрели, запускаются. Повторная запись той же строки список не меняет: реакции не запускаются. Запись в индекс дальше текущей длины удлиняет список и тоже его меняет.

Чтение `items[0]` в реакции — это уже взгляд на список. Отдельной подписки «только на нулевой слот» нет. `push`, который нулевой слот не трогал, эту реакцию всё равно запускает.

#### Длина

`items.length` — чтение того же списка. `this.items.length = 0` очищает список. `push` и `pop` меняют длину тем же сигналом. Реакция, которая заглянула только в `length`, видит и очистку, и `push`, и смену первого слота.

#### push и проход по списку

`push` дописывает элемент в конец. `pop`, `shift`, `unshift` и `splice` меняют тот же список. Реакция подключается к нему, когда вызывает `join`, `map`, `forEach` или читает слот либо длину.

`map` и `filter`, вызванные на наблюдаемом массиве, возвращают обычный массив. Для подписки важно само обращение к ним внутри прохода. Что делать с возвращённым обычным массивом дальше — advanced, п. 22.

---

#### Пример

```javascript
import { makeAutoObservable, autorun } from "mobx"

const cart = makeAutoObservable({
    items: ["a"],
    push(item) {
        this.items.push(item)
    },
    renameFirst(item) {
        this.items[0] = item
    },
    clear() {
        this.items.length = 0
    }
})

const log = []
autorun(() => {
    log.push(cart.items.join(","))
})
// log равен ["a"]

cart.push("b")
// log равен ["a", "a,b"]

cart.renameFirst("z")
// log равен ["a", "a,b", "z,b"]

cart.clear()
// log равен ["a", "a,b", "z,b", ""]
```

`join` заглядывает в список. `push` дописывает `"b"`, запись в нулевой слот меняет `"a"` на `"z"`, `length = 0` очищает список. Каждый из трёх методов даёт одну новую строку лога. Отдельной подписки на метод не было.

---

#### Ловушка

Упоминание массива без слота, длины и прохода смотрит на ячейку, а не на список внутри неё.

```javascript
import { makeAutoObservable, autorun } from "mobx"

const cart = makeAutoObservable({
    items: ["a"],
    push(item) {
        this.items.push(item)
    },
    replace(items) {
        this.items = items
    }
})

const log = []
autorun(() => {
    log.push(cart.items)
})
cart.push("b")
// log содержит одну запись
// cart.items.length равен 2

cart.replace(["c"])
// log содержит две записи
// cart.items.join(",") равен "c"
```

`push` меняет список, который реакция не открывала. Длина уже `2`, а второй записи в логе нет. `replace` меняет само поле `items`, и это поле реакция читала. Внутри `autorun` вызывайте `join`, `map` или читайте `length`, когда лог должен расти от `push`.

---

#### Сводка

| Что сделал проход | `push`, запись индекса, смена `length` |
|---|---|
| Прочитал слот, `length`, `join`, `map` или `forEach` | Запускают реакцию |
| Только назвал поле с массивом | Не запускают; запуск даёт замена поля |

В обычной работе список открывают там, где рисуют его содержимое. Замену массива целиком оставляют отдельному присваиванию поля.

#### Граница инструмента

Общий сигнал списка — это MobX. Обычный массив JavaScript от `push` никого не зовёт. Поэлементные подписки у этого массива нет: слот, длина и проход смотрят на один список.

#### Чем закрыть тему

Направьте `autorun` на `items.join(",")`. Вызовите `push`, запишите новый нулевой элемент и обнулите `length`. Проверьте, что в логе четыре строки: начальная и по одной на каждый метод. В другом `autorun` только упомяните `items`, снова вызовите `push` и проверьте, что этот лог не вырос, а `length` вырос.

Уровень base по оглавлению закончен.
