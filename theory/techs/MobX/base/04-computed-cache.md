# A computed getter caches and does not notify when the result is unchanged

Детализация п. 4 уровня «base», MobX. Оглавление: [index.md](./index.md).

Конспект: сначала о чём речь и зачем это нужно на этом уровне, потом устройство, пример, ловушка и короткая формулировка, с которой тему можно закрыть.

#### О чём речь

Геттер на помеченном объекте — это derivation: `order.total` выглядит как поле и считается из других полей. Пока им пользуется реакция, MobX кэширует результат и снова выполняет геттер только после изменения входа. Реакции, которые читают геттер, запускаются снова только когда следующий результат — другое значение. Без кэша каждое чтение повторяет работу. Без сравнения реакция запускается, когда вход шевельнулся, а нужное число осталось прежним.

---

#### Модель

`total` — ячейка с формулой из этот уровень, п. 1. Когда реакция впервые её читает, формула выполняется и результат сохраняется. Дальнейшие чтения, пока эта реакция жива, берут сохранённый результат, пока не изменятся `price` или `amount`. Тогда формула выполняется снова. Если новый результат — то же значение, диаграмма не перерисовывается.

То же число, строка или boolean считаются неизменным результатом. Заново созданный объект считается изменившимся, даже если свойства внутри совпадают.

---

#### Тело выполняется, когда результат нужен

Геттер не выполняется оттого лишь, что изменился `price`. Он выполняется, когда кто-то читает `total`. Если `total` никто не читает, смена `price` тело не запускает. Пока реакция читает `total`, два упоминания `order.total` за один запуск делят один расчёт. Тело выполняется снова, когда меняется вход предыдущего расчёта.

#### Тот же результат пропускает реакцию

После выполнения тела MobX сравнивает новый результат с предыдущим. То же число или boolean значит, что реакции, которые зависят от этого геттера, не запускаются. Тело выполнилось, потому что изменился вход. Реакция не запустилась, потому что ответ не изменился. Другое число запускает реакцию один раз.

#### Новый объект — новый результат

Вернуть `{ empty: true }`, а потом другой `{ empty: true }` — это два объекта. Реакция запускается снова и видит тот же `true`. Возвращайте сам boolean, когда он и есть настоящий результат. Сравнение, которое заглядывает внутрь объекта, — advanced, п. 21.

Кэш держится, пока за геттером наблюдает реакция. Когда последняя реакция останавливается, следующее голое чтение считает заново. Кэш без читателей — advanced, п. 32.

---

#### Пример

```javascript
import { makeAutoObservable, autorun } from "mobx"
const cart = makeAutoObservable({
    price: 2,
    amount: 0,
    get total() {
        console.log("считаю")
        return this.price * this.amount
    }
})
const totals = []
autorun(() => {
    totals.push(cart.total)
})
// считаю
// totals равен [0]
cart.price = 5
// считаю
// totals по-прежнему [0]
cart.amount = 2
// считаю
// totals равен [0, 10]
```

Первое чтение запоминает `0`. `price = 5` меняет вход, геттер выполняется и снова возвращает `0`. `totals` остаётся `[0]`. `amount = 2` делает результат `10`, и реакция запоминает `10`.

---

#### Ловушка

Новый объект на каждый расчёт ломает сравнение.

```javascript
import { makeAutoObservable, autorun } from "mobx"
const cart = makeAutoObservable({
    amount: 1,
    get badge() {
        return { even: this.amount % 2 === 0 }
    }
})
const flags = []
autorun(() => {
    flags.push(cart.badge.even)
})
cart.amount = 3
// flags равен [false, false]
```

И `1`, и `3` нечётные, поэтому `even` оба раза `false`. `badge` возвращает новый объект, результат считается изменившимся, и реакция второй раз запоминает `false`. Возвращайте `this.amount % 2 === 0`, когда реакции нужен только boolean. Те же шаги тогда оставляют `flags` равным `[false]`.

---

#### Сводка

| Что возвращает геттер | После смены входа реакция |
|---|---|
| То же число или boolean | Не запускается |
| Другое число или boolean | Запускается один раз |
| Новый объект | Запускается один раз |

Возвращайте число, строку или boolean, когда это и есть ответ. Читайте геттер из реакции, когда результат нужно хранить между изменениями.

#### Граница инструмента

Кэш и сравнение — это MobX. Геттер остаётся геттером JavaScript: тело выполняется, когда MobX не может взять результат из кэша.

#### Чем закрыть тему

Следите за `total` из `autorun`. Измените вход так, чтобы `total` остался тем же, и проверьте, что тело геттера выполнилось, а лог не вырос. Измените вход так, чтобы `total` изменился, и проверьте, что лог получил новое число.

Уровень base по оглавлению закончен.
