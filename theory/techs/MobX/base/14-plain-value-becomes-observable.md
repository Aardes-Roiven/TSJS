# A plain object or array assigned into an observable field becomes observable

Детализация п. 14 уровня «base», MobX. Оглавление: [index.md](./index.md).

Конспект: сначала о чём речь и зачем это нужно на этом уровне, потом устройство, пример, ловушка и короткая формулировка, с которой тему можно закрыть.

#### О чём речь

В наблюдаемое поле можно положить обычный объект или обычный массив, собранный только что. MobX кладёт в поле уже наблюдаемую копию. Поля копии и элементы массива видны реакциям. Переменная, из которой присваивали, остаётся прежней и наблюдаемой не становится. Правка этой переменной экран не обновляет, и имя в заказе тоже не меняется. Кажется, что присваивание «включило» исходный объект. Включилась копия в поле.

---

#### Модель

Ячейка принимает простой объект и оставляет у себя другой объект с теми же полями. Стрелки есть у копии. Исходный объект остаётся обычным: его поля реакции не видят, и запись в них ячейку не двигает.

Вложенный простой объект копируется так же. У `profile.address.city` стрелка есть, если `address` пришёл внутри присвоенного объекта. Массив копируется в наблюдаемый список: `push` по полю заказа будит реакции (этот уровень, п. 12). `push` по исходному массиву поле не меняет.

Экземпляр класса в ту же ячейку копией не становится (этот уровень, п. 15).

---

#### Объект в поле

`this.profile = { name: "a" }` кладёт в `profile` наблюдаемый объект. `order.profile.name` можно читать из `autorun` и присваивать из action. `order.profile === plain` равен `false`. У копии те поля, которые были у простого объекта в момент присваивания.

Поле, добавленное на эту копию уже после присваивания, — advanced, п. 24. Сам вызов `makeAutoObservable` поздние поля своего объекта не помечает (этот уровень, п. 16).

#### Массив в поле

`this.items = ["a", "b"]` кладёт в поле наблюдаемый список. Исходный массив — другой. `order.items.push("c")` меняет список в ячейке. `plain.push("c")` меняет только `plain`.

#### Вложенные простые значения

`{ address: { city: "a" } }` даёт наблюдаемыми и внешний объект, и `address`. Реакция, которая читает `order.profile.address.city`, запускается после `order.profile.address.city = "b"`. Число, строка и boolean копируются как значения. Стрелка у них на поле, которое их держит (этот уровень, п. 3).

---

#### Пример

```javascript
import { makeAutoObservable, autorun } from "mobx"

const order = makeAutoObservable({
    profile: { name: "old" },
    setProfile(next) {
        this.profile = next
    },
    rename(name) {
        this.profile.name = name
    }
})

const plain = { name: "a" }
order.setProfile(plain)
const log = []
autorun(() => {
    log.push(order.profile.name)
})
// log равен ["a"]
// order.profile === plain равен false

plain.name = "b"
// log равен ["a"]
// order.profile.name равен "a"
// plain.name равен "b"

order.rename("c")
// log равен ["a", "c"]
```

`setProfile` кладёт в ячейку копию с именем `"a"`. Запись в `plain.name` оставляет и лог, и `order.profile.name` на `"a"`. `rename` пишет уже поле копии, и лог получает `"c"`.

---

#### Ловушка

Дальнейшая сборка заказа из исходного массива правит не тот список, который читает реакция.

```javascript
import { makeAutoObservable, autorun } from "mobx"

const order = makeAutoObservable({
    items: ["a"],
    setItems(next) {
        this.items = next
    },
    push(item) {
        this.items.push(item)
    }
})

const plain = ["a", "b"]
order.setItems(plain)
const log = []
autorun(() => {
    log.push(order.items.join(","))
})
plain.push("c")
// log равен ["a,b"]
// order.items.join(",") равен "a,b"

order.push("c")
// log равен ["a,b", "a,b,c"]
```

`plain` и список в `order.items` разошлись в момент `setItems`. Элемент добавляйте методом поля, которое читает реакция.

---

#### Сводка

| Что присвоили в поле | Что лежит в поле | Что осталось в переменной |
|---|---|---|
| Простой объект | Наблюдаемая копия с теми же полями | Прежний простой объект |
| Простой массив | Наблюдаемый список с теми же элементами | Прежний массив |
| Вложенный простой объект | Наблюдаемая копия на каждом уровне | Прежняя структура |

После присваивания читайте и пишите `order.profile` или `order.items`. Исходную переменную для следующих правок не используйте.

#### Граница инструмента

Копию делает MobX, когда поле помечено как глубоко наблюдаемое. Это обычный путь `makeAutoObservable`. Поле, которое хранит значение без превращения в observable, задаётся иначе: advanced, п. 18. Экземпляр класса этот путь не копирует (этот уровень, п. 15).

#### Чем закрыть тему

Присвойте в поле объект из переменной. Проверьте, что переменная и `order.profile` — разные ссылки. Поменяйте поле у переменной и убедитесь, что лог реакции не вырос и имя в заказе прежнее. Поменяйте `order.profile.name` из метода и проверьте, что лог получил новое имя.

Уровень base по оглавлению закончен.
