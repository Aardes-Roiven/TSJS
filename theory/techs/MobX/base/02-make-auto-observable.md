# makeAutoObservable

Детализация п. 2 уровня «base», MobX. Оглавление: [index.md](./index.md).

Конспект: сначала о чём речь и зачем это нужно на этом уровне, потом устройство, пример, ловушка и короткая формулировка, с которой тему можно закрыть.

#### О чём речь

Обычный объект никого не уведомляет, когда меняется поле. `makeAutoObservable` помечает поля, геттеры и методы экземпляра класса или простого объекта, чтобы три роли из этот уровень, п. 1 действительно заработали. Без этого вызова `autorun` печатает первые значения и дальше молчит. Это похоже на сломанную подписку. Следующие темы считают, что вызов уже сделан.

---

#### Модель

Заказ описывают обычным классом или обычным объектом, затем один раз передают в `makeAutoObservable`. MobX смотрит на члены, которые уже есть, и назначает каждому роль. Вызов не вешает слушателя. Реакции начнутся позже, когда кто-то прочитает поле.

Вызывайте его на `this` из конструктора. Инициализаторы полей выполняются до тела конструктора, поэтому к моменту вызова поля уже есть. Члены, которые появляются только после этого вызова, — этот уровень, п. 16.

---

#### Поля, геттеры и методы

Поле со значением становится observable state. `count = 0` можно читать и присваивать, и реакции видят присваивание. Геттер становится derivation. `get total()` читают как поле, и результат кэшируется, пока им кто-то пользуется (этот уровень, п. 4). Метод становится action: это функция, которой меняют поля (этот уровень, п. 5). Снаружи по-прежнему пишут `order.count`, `order.total` и `order.add(1)`.

Сеттер считается action. Пара с геттером — advanced, п. 31. Метод-генератор считается `flow`; случай, когда компилятор прячет генератор, — advanced, п. 7.

#### Класс или один простой объект

Класс нужен, когда заказов больше одного. Каждый экземпляр помечается в своём конструкторе. Один счётчик может быть самим объектом: `makeAutoObservable({ count: 0, add() { this.count += 1 } })`. Вызов `add` ставит `this` на этот объект. Роли те же: `count` — состояние, `add` — action.

#### Один раз на объект

Помечайте объект в момент создания. Второй `makeAutoObservable` на том же объекте бросает ошибку. Подклассу нужны `makeObservable` и `override` (advanced, п. 28).

---

#### Пример

```javascript
import { makeAutoObservable, autorun } from "mobx"

class Order {
    amount = 1

    constructor() {
        makeAutoObservable(this)
    }

    add(extra) {
        this.amount += extra
    }
}

const order = new Order()
const log = []
autorun(() => {
    log.push(order.amount)
})
order.add(2)
// log равен [1, 3]
```

Конструктор помечает `amount` и `add`. Реакция запоминает `1`. `order.add(2)` присваивает `amount`. Реакция запускается снова, и лог равен `[1, 3]`.

---

#### Ловушка

Если вызов забыть, первый `autorun` всё равно выполнится, и поломку легко не заметить.

```javascript
import { autorun } from "mobx"

class Order {
    amount = 1

    add(extra) {
        this.amount += extra
    }
}

const order = new Order()
const log = []
autorun(() => {
    log.push(order.amount)
})
order.add(2)
// log равен [1]
// order.amount равен 2
```

`add` изменил `amount` на `2`. Реакция больше не запускается, потому что поле не было помечено. Поставьте `makeAutoObservable(this)` в конструктор, и те же шаги дадут `[1, 3]`.

---

#### Сводка

Вызывайте `makeAutoObservable` один раз при создании. Поля хранят состояние, геттеры производят значения, методы меняют состояние. Класс — когда экземпляров много, простой объект — когда он один.

#### Граница инструмента

TypeScript по-прежнему видит обычный класс. Пропущенный вызов — не ошибка типов. Он виден в рантайме, как в ловушке: поле меняется, а реакция нет.

#### Чем закрыть тему

Вызовите `makeAutoObservable(this)` в конструкторе и проверьте, что `autorun` записывает новое значение поля после вызова метода. Уберите вызов, повторите шаги и проверьте, что поле меняется, а лог остаётся на первом значении.

Уровень base по оглавлению закончен.
