# A class instance assigned into a field is not made observable

Детализация п. 15 уровня «base», MobX. Оглавление: [index.md](./index.md).

Конспект: сначала о чём речь и зачем это нужно на этом уровне, потом устройство, пример, ловушка и короткая формулировка, с которой тему можно закрыть.

#### О чём речь

Простой объект, положенный в наблюдаемое поле, становится наблюдаемой копией (этот уровень, п. 14). Экземпляр класса в то же поле остаётся этим экземпляром. Замена поля `note` реакции видна. Запись в `note.title` реакцию не будит, пока сам класс не пометил свои поля. Экран держит первое название, хотя `order.note.title` уже другое. Класс, похожий на мешок полей, здесь ведёт себя как обычный объект JavaScript.

---

#### Модель

Ячейка `note` хранит ссылку. Стрелка есть у ячейки. Внутри экземпляра стрелок нет, если конструктор `Note` сам не вызвал `makeAutoObservable(this)` (этот уровень, п. 2). Присваивание в поле заказа эту разметку не добавляет.

`order.note === note` остаётся `true`. Это тот же экземпляр, не копия. Поля экземпляра меняются записью в них. Реакция, которая их прочитала, в список зависимостей эти поля не ставит: наблюдать там нечего (этот уровень, п. 11).

---

#### Ссылка в поле наблюдаема

`this.note = other` заменяет ячейку. Реакция, которая читает `order.note` или `order.note.title`, запускается снова и видит уже другой экземпляр. Для этого `Note` помечать не нужно. Поле заказа помечено, и проход заглянул в него.

#### Поля экземпляра остаются обычными

`this.note.title = "b"` меняет свойство экземпляра. Реакция, уже прочитавшая `order.note.title`, снова не запускается. Следующее ручное чтение `order.note.title` возвращает `"b"`. Лог остаётся на первом значении. Расхождение такое же, как у обычного `let`: значение ушло вперёд, а реакция осталась на проходе, где наблюдать было нечего.

#### Разметку делает конструктор класса

`class Note { title = "a"; constructor() { makeAutoObservable(this) } }` помечает `title` в момент создания экземпляра. Тогда `order.note.title = "b"` будит реакцию, которая это поле читает. Поле заказа тут ни при чём. Экземпляр пришёл уже размеченным. Два пути не смешиваются: простой объект размечает присваивание в поле, экземпляр класса размечает его конструктор.

---

#### Пример

```javascript
import { makeAutoObservable, autorun } from "mobx"

class Note {
    title = "a"
    constructor() {
        makeAutoObservable(this)
    }
    rename(title) {
        this.title = title
    }
}

const order = makeAutoObservable({
    note: new Note(),
    retitle(title) {
        this.note.rename(title)
    }
})

const log = []
autorun(() => {
    log.push(order.note.title)
})
order.retitle("b")
// log равен ["a", "b"]
```

`Note` помечает себя в конструкторе. `title` — наблюдаемое поле экземпляра. `retitle` пишет его через метод заметки, и лог получает `"b"`. Заказ только хранит ссылку и вызывает метод.

---

#### Ловушка

Класс без `makeAutoObservable` принимает новое название и реакцию не будит.

```javascript
import { makeAutoObservable, autorun } from "mobx"

class Note {
    title = "a"
    rename(title) {
        this.title = title
    }
}

const order = makeAutoObservable({
    note: new Note(),
    retitle(title) {
        this.note.rename(title)
    },
    replace(note) {
        this.note = note
    }
})

const log = []
autorun(() => {
    log.push(order.note.title)
})
order.retitle("b")
// log равен ["a"]
// order.note.title равен "b"

const next = new Note()
next.title = "c"
order.replace(next)
// log равен ["a", "c"]
```

`retitle` меняет обычное свойство. Проход его не отслеживает, лог остаётся `["a"]`, в поле уже `"b"`. `replace` меняет наблюдаемую ячейку `note`, проход читает `title` нового экземпляра и записывает `"c"`. Поля заметки заработают, когда конструктор `Note` вызовет `makeAutoObservable(this)`.

---

#### Сводка

| Что изменилось | Экземпляр без разметки | Экземпляр, помеченный в конструкторе |
|---|---|---|
| `order.note = other` | Реакция видит другой экземпляр | Реакция видит другой экземпляр |
| `note.title = "b"` | Значение меняется, реакция молчит | Реакция получает `"b"` |

Данные с полями, за которыми нужно следить, либо оставляйте простым объектом в наблюдаемом поле, либо помечайте класс в его конструкторе.

#### Граница инструмента

MobX сам экземпляр класса в observable не превращает. Это правило присваивания в поле. Разметка полей класса делается только явным `makeAutoObservable` или `makeObservable` в этом классе.

#### Чем закрыть тему

Положите в поле экземпляр без `makeAutoObservable`, прочитайте `title` из `autorun` и поменяйте `title`. Проверьте, что лог не вырос, а свойство уже новое. Замените поле другим экземпляром и проверьте, что лог увидел его `title`. Добавьте `makeAutoObservable(this)` в конструктор и проверьте, что смена `title` дописывает лог.

Уровень base по оглавлению закончен.
