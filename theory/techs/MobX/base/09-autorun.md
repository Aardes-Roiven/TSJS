# autorun

Детализация п. 9 уровня «base», MobX. Оглавление: [index.md](./index.md).

Конспект: сначала о чём речь и зачем это нужно на этом уровне, потом устройство, пример, ловушка и короткая формулировка, с которой тему можно закрыть.

#### О чём речь

`autorun` — это reaction, которую запускают руками. Функция читает наблюдаемые поля и делает побочный эффект. MobX выполняет её один раз сразу, затем снова после того, как action изменил эти поля. Без него функцию обновления вызывают сами после каждого action. Как остановить реакцию — этот уровень, п. 10. Какие чтения внутри функции считаются — этот уровень, п. 11.

---

#### Модель

Создание `autorun` сразу рисует диаграмму из этот уровень, п. 1 по ячейкам, какими они есть сейчас. Законченный action, который эти ячейки изменил, рисует её снова. Для второй отрисовки функцию не вызывают.

Работа функции — побочный эффект: дописать в лог, отправить запрос, записать на страницу. Возврат функции MobX выбрасывает. Значение, которое нужно читать позже, — это геттер (этот уровень, п. 4), а не возврат из `autorun`.

---

#### Первый запуск происходит до возврата autorun

`autorun(() => { ... })` выполняет функцию до вашей следующей строки. Если `amount` равен `2`, эффект записывает `2`, хотя `add` ещё не вызывали. Первая строка лога — текущее состояние. Поздние строки — изменения. Этот первый запуск ещё и записывает, какие поля эффект прочитал.

#### Поздние запуски идут за законченным action

Когда action присваивает поле, которое эффект читал, функция выполняется снова с начала и видит новые значения. Один action, который присваивает несколько полей, даёт один дополнительный запуск (этот уровень, п. 6). В середине action эффект не выполняется. Поле, которое эффект ни разу не читал, может измениться без дополнительного запуска (этот уровень, п. 11).

---

#### Пример

```javascript
import { makeAutoObservable, autorun } from "mobx"

const order = makeAutoObservable({
    amount: 2,
    add() {
        this.amount += 1
    }
})

const log = []
autorun(() => {
    log.push(order.amount)
})
// log равен [2]

order.add()
// log равен [2, 3]
```

`autorun` записывает `2` до всякого action. `order.add()` присваивает `amount`, и функция записывает `3`. Проверка, которая ждёт `[]` до первого `add`, не проходит: текущее количество уже первая запись. Запись после `add` — это обновление.

---

#### Ловушка

Функция, возвращённая из эффекта, никогда не вызывается. Она не останавливает реакцию и не выполняется как очистка.

```javascript
import { makeAutoObservable, autorun } from "mobx"

const order = makeAutoObservable({
    amount: 1,
    add() {
        this.amount += 1
    }
})

let returned = 0
autorun(() => {
    void order.amount
    return () => {
        returned += 1
    }
})
order.add()
// returned равен 0
```

`order.add()` изменил `amount`, и эффект выполнился снова. `returned` остаётся `0`. Останавливает функция, которую возвращает `autorun`, а не функция, которую возвращает эффект (этот уровень, п. 10).

---

#### Сводка

Создайте `autorun` один раз. Первый запуск записывает текущие поля. Каждый законченный action, который меняет прочитанное поле, даёт ещё один запуск. Тело используйте для побочного эффекта. Останавливайте реакцию функцией, которую возвращает `autorun` (этот уровень, п. 10).

#### Граница инструмента

`autorun` — это MobX. Функция, возвращённая из колбэка, не является очисткой так, как ею является возврат эффекта React.

#### Чем закрыть тему

Дописывайте `order.amount` из `autorun` и проверьте, что массив держит текущее количество до всякого action. Вызовите метод, который меняет `amount`, и проверьте, что массив получил одно число. Верните функцию из эффекта, снова измените `amount` и проверьте, что возвращённую функцию не вызывали.

Уровень base по оглавлению закончен.
