# Observable state, derivations, and reactions

Детализация п. 1 уровня «base», MobX. Оглавление: [index.md](./index.md).

Конспект: сначала о чём речь и зачем это нужно на этом уровне, потом устройство, пример, ловушка и короткая формулировка, с которой тему можно закрыть.

#### О чём речь

MobX разделяет три вида работы: данные, которые вы меняете; значение, посчитанное из этих данных; побочный эффект, который должен выполниться снова, когда данные изменились. Без этого разделения каждое изменение приходится вручную раздавать всем слушателям, и первая программа либо пропускает обновление, либо перерисовывает всё. Имена такие: observable state, derivation и reaction. Дальше на этом уровне они становятся конкретными: `makeAutoObservable`, поле, геттер, action и `autorun`.

---

#### Модель

Держите в голове электронную таблицу. Ячейка ввода — это данные, которые вы набираете. Ячейка с формулой показывает число, посчитанное из ячеек ввода. Диаграмма перерисовывается, когда результат формулы меняется. Вы не говорите диаграмме, за какими ячейками следить. Таблица сама замечает, какие ячейки формула использовала.

Observable state — это ячейка ввода. Derivation — это формула: её читают, и она считается из состояния. Reaction — это диаграмма: она делает побочный эффект и не отдаёт значение, которое потом читают. `autorun` — первая reaction (этот уровень, п. 9). Геттер `computed` — это derivation (этот уровень, п. 4). Обычная переменная JavaScript ячейкой ввода не является. Присваивание меняет только её саму.

---

#### Наблюдаемое состояние

Observable state — это данные, которые меняются со временем: счётчик, имя, заказ. Они живут на объекте, который вы передаёте MobX (этот уровень, п. 2). После этого чтение поля и присваивание поля видны производным значениям и реакциям. Состояние само не запускается. Что-то пересчитывается потому, что derivation или reaction прочитали поле, а потом поле изменилось.

#### Производное значение

Derivation — это значение, определённое через другие значения. `order.total` читают так же, как поле. Его не вызывают, чтобы обновить экран. Пока им кто-то пользуется, MobX может пропустить работу, если входы не изменились, и может не будить реакции, если результат остался тем же значением (этот уровень, п. 4). Derivation отвечает на вопрос «какой итог?». Запись в лог, запрос или перерисовка — это reaction.

#### Реакция

Reaction делает побочный эффект и запускается снова, когда меняется observable state, которое она прочитала. Её создают один раз. Подписываться на каждое поле отдельно не нужно. Возврат функции — не результат программы. Результат — сам эффект: строка лога, запрос, обновлённый виджет.

---

#### Пример

```javascript
import { makeAutoObservable, autorun } from "mobx"

const order = makeAutoObservable({
    price: 2,
    amount: 0,
    get total() {
        return this.price * this.amount
    }
})

const log = []
autorun(() => {
    log.push(order.total)
})
order.amount = 3
// log равен [0, 6]

order.price = 5
// log равен [0, 6, 15]
```

`price` и `amount` — observable state. `total` — derivation. `autorun` — reaction: она читает `total`, а `total` читает `amount`. Присваивание `amount = 3` дописывает `6`. Присваивание `price = 5` дописывает `15`. Слушателя ни на одно поле не регистрировали. Тело реакции по-прежнему читает только `order.total`.

---

#### Ловушка

Обычная переменная не становится наблюдаемой оттого, что её прочитал `autorun`.

```javascript
import { autorun } from "mobx"

let amount = 0
const log = []
autorun(() => {
    log.push(amount)
})
amount = 3
// log равен [0]
```

Функция один раз выполнилась и увидела `0`. `amount = 3` меняет переменную. Наблюдаемой записи нет, поэтому функция больше не запускается. Положите `amount` на объект, переданный в `makeAutoObservable`, и присваивайте `order.amount`.

---

#### Сводка

| Вид | Для чего | Когда запускается снова |
|---|---|---|
| Observable state | Значения, которые вы меняете | Само не запускается: его меняете вы |
| Derivation | Значение, посчитанное из состояния | Когда меняются его входы |
| Reaction | Побочный эффект | Когда меняется прочитанное состояние |

Меняющиеся данные храните как observable state, посчитанные числа отдавайте как derivation, а логи, запросы и отрисовку кладите в reaction. Какие именно чтения входят в зависимость — этот уровень, п. 11.

---

#### Граница инструмента

Это разделение целиком внутри MobX. JavaScript не перезапускает функцию из-за того, что изменилась переменная.

#### Чем закрыть тему

На маленьком объекте подпишите каждый кусок: состояние, производное значение или реакция. Измените одно поле и проверьте, что лог реакции получил новое производное значение. Измените обычный `let`, который читает другой `autorun`, и проверьте, что этот второй лог остаётся из одной записи.

Уровень base по оглавлению закончен.
