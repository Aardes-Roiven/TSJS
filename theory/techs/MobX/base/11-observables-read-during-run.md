# Only observables read during the run become dependencies

Детализация п. 11 уровня «base», MobX. Оглавление: [index.md](./index.md).

Конспект: сначала о чём речь и зачем это нужно на этом уровне, потом устройство, пример, ловушка и короткая формулировка, с которой тему можно закрыть.

#### О чём речь

Реакция запускается снова только из-за тех наблюдаемых полей, которые она прочитала, пока функция выполнялась. Поле, до которого эта функция не дошла, может измениться, и диаграмма останется на месте. Чтение, которое случается уже после возврата функции, в список тоже не входит. Без этого правила кажется, что `autorun` следит за всем объектом. Первая проверка тогда ждёт лишнюю строку лога либо не дожидается нужной.

---

#### Модель

Диаграмма из этот уровень, п. 1 перерисовывается по ячейкам, в которые формула заглянула за этот проход. Список ячеек собирается заново при каждом проходе. Ячейка, мимо которой проход прошёл, из списка выпадает. Следующая правка этой ячейки диаграмму не будит, пока какой-нибудь поздний проход снова в неё не заглянет.

Проход — это синхронное выполнение отслеживаемой функции: тело `autorun` (этот уровень, п. 9), тело геттера, пока его читают (этот уровень, п. 4), позже — рендер `observer` (этот уровень, п. 17). Функция, вызванная прямо из этого тела, ещё внутри прохода. Колбэк, отложенный на потом, уже снаружи.

---

#### Поле, прочитанное в этот проход

`order.amount` внутри тела — это заглядывание в ячейку. Присваивание `amount` после законченного action запускает реакцию снова. Деструктуризация в том же теле делает то же чтение: `const { amount } = order` заглядывает в `amount`. Чтение через вызванную функцию тоже считается, если вызов происходит до возврата из тела.

Геттер, который тело прочитало, входит в список как эта формула. Поля, которые прочитала сама формула, относятся к её проходу. Реакция, которая видит только `order.total`, запускается снова, когда меняется результат `total` (этот уровень, п. 4).

#### Поле, мимо которого проход прошёл

Ветка, которая не выполнилась, поля не читает. Пока `visible` равен `false` и тело пишет `"hidden"`, `amount` в списке нет. `setAmount` диаграмму не будит. Проход, который выполнил другую ветку и прочитал `amount`, ставит `amount` в новый список. Следующий `setAmount` уже будит.

Поле `label`, которое тело не называет ни в одной ветке, в список не входит. Его присваивание эту реакцию не запускает.

#### Чтение после возврата

`setTimeout`, `promise.then` и код после `await` выполняются, когда проход уже кончился. Поле, прочитанное там, в список этого прохода не записывается. К моменту колбэка в поле лежит уже новое значение, если его успели присвоить. Реакция из-за этого присваивания не запускалась.

---

#### Пример

```javascript
import { makeAutoObservable, autorun } from "mobx"

const order = makeAutoObservable({
    visible: false,
    amount: 1,
    label: "a",
    show() {
        this.visible = true
    },
    setAmount(next) {
        this.amount = next
    },
    setLabel(next) {
        this.label = next
    }
})

const log = []
autorun(() => {
    if (order.visible) log.push(order.amount)
    else log.push("hidden")
})
order.setAmount(5)
order.setLabel("b")
// log равен ["hidden"]

order.show()
// log равен ["hidden", 5]

order.setAmount(6)
// log равен ["hidden", 5, 6]

order.setLabel("c")
// log по-прежнему ["hidden", 5, 6]
```

Первый проход заглянул только в `visible` и записал `"hidden"`. `setAmount(5)` меняет поле, которого в списке нет. `show` меняет `visible`, проход заглядывает в `amount` и записывает `5`. Теперь `setAmount(6)` дописывает `6`. `label` по-прежнему никто не читал.

#### Ловушка

Чтение в отложенном колбэке выглядит как чтение внутри `autorun` и зависимость не создаёт.

```javascript
import { makeAutoObservable, autorun } from "mobx"

const order = makeAutoObservable({
    amount: 1,
    label: "a",
    setAmount(next) {
        this.amount = next
    },
    setLabel(next) {
        this.label = next
    }
})

let runs = 0
autorun(() => {
    runs += 1
    const amount = order.amount
    setTimeout(() => {
        void order.label
        void amount
    }, 0)
})
order.setLabel("b")
// runs равен 1

order.setAmount(2)
// runs равен 2
```

Тело прочитало `amount`, поэтому `setAmount` даёт второй проход. `order.label` назван только внутри `setTimeout`. `setLabel` число проходов не меняет. Читайте поле в теле, до возврата из функции, которую передали в `autorun`.

---

#### Сводка

| Где прочитано поле | Входит в список этого прохода |
|---|---|
| В теле или в функции, вызванной из тела | Да |
| В ветке, которая не выполнилась | Нет, пока какой-нибудь проход её не выполнит |
| В `setTimeout`, после `await`, в `then` | Нет |

Меняйте список зависимостей тем, какие поля тело читает в этом проходе. Отложенное чтение перенесите в тело либо заведите отдельную реакцию, которая читает это поле сама.

#### Граница инструмента

Список чтений ведёт MobX. JavaScript функцию из-за присваивания заново не вызывает. Отложенный колбэк остаётся обычным колбэком: MobX проход на него не продлевает.

#### Чем закрыть тему

Запустите `autorun` с веткой, которая читает одно поле. Присвойте другое поле и проверьте, что лог не вырос. Войдите в ветку, которая это поле читает, присвойте его и проверьте, что лог получил новое значение. Перенесите одно чтение в `setTimeout` и проверьте, что присваивание этого поля число проходов не меняет.

Уровень base по оглавлению закончен.
