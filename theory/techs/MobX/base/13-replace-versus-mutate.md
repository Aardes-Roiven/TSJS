# Replacing an object or array versus mutating it

Детализация п. 13 уровня «base», MobX. Оглавление: [index.md](./index.md).

Конспект: сначала о чём речь и зачем это нужно на этом уровне, потом устройство, пример, ловушка и короткая формулировка, с которой тему можно закрыть.

#### О чём речь

Правка пишет в поле того объекта, который уже лежит в ячейке. Замена кладёт в ячейку другой объект или другой массив. Реакция, которая каждый раз читает `order.item.name`, видит оба жеста: она заглядывает и в ячейку `item`, и в `name`. Реакция, которая держит прежний объект и читает уже его `name`, замену ячейки не видит. Она остаётся на старом объекте. Экран, замкнутый на первую ссылку, показывает старое имя, хотя поле заказа уже указывает на новый объект.

---

#### Модель

Стрелка из ячейки `item` ведёт к объекту. Стрелка `name` ведёт от этого объекта к строке. Правка двигает вторую стрелку. Замена двигает первую и оставляет прежний объект на месте, вместе с теми, кто его ещё держит.

Тот же рисунок у массива. `push` и запись индекса меняют текущий список (этот уровень, п. 12). `this.items = ["c"]` двигает стрелку поля `items`. Кто на каждом проходе читает `order.items.join(",")`, видит и правку, и замену. Кто сохранил прежний массив и вызывает `join` уже у него, видит только правку этого массива.

Простой объект, положенный в ячейку при замене, становится наблюдаемым (этот уровень, п. 14). Здесь важно, кого какая стрелка будит.

---

#### Правка текущего объекта

`this.item.name = "b"` пишет поле того объекта, на который сейчас указывает `item`. Реакция, читающая `order.item.name`, запускается и видит `"b"`. Реакция, которая раньше взяла тот же объект в переменную и читает `held.name`, тоже запускается: `held` и `order.item` пока один объект.

#### Замена ячейки

`this.item = { name: "c" }` ставит в ячейку другой объект. Реакция, которая на следующем проходе снова читает `order.item.name`, видит `"c"`. Прежний объект остаётся с `"b"`. Реакция, замкнутая на него, новый проход не получает.

#### Массив в том же поле

`this.items.push("b")` правит текущий список. `this.items = ["c"]` заменяет поле. Проход, который каждый раз вызывает `cart.items.join(",")`, записывает и `"a,b"`, и `"c"`. Переменная, в которую список скопировали до замены, после замены указывает на прежний список.

---

#### Пример

```javascript
import { makeAutoObservable, autorun } from "mobx"

const order = makeAutoObservable({
    item: { name: "a" },
    rename(name) {
        this.item.name = name
    },
    replace(name) {
        this.item = { name }
    }
})

const throughField = []
autorun(() => {
    throughField.push(order.item.name)
})
const held = order.item
const throughHeld = []
autorun(() => {
    throughHeld.push(held.name)
})
order.rename("b")
// throughField равен ["a", "b"]
// throughHeld равен ["a", "b"]

order.replace("c")
// throughField равен ["a", "b", "c"]
// throughHeld равен ["a", "b"]
// held.name равен "b"
// order.item.name равен "c"
```

`rename` пишет `name` у текущего объекта, поэтому растут оба лога. `replace` двигает ячейку `item`. Проход через `order.item.name` видит `"c"`. `held` остаётся прежним объектом с именем `"b"`, и его лог молчит.

---

#### Ловушка

Правка отдельной копии ячейку не двигает и объект в ячейке не меняет.

```javascript
import { makeAutoObservable, autorun } from "mobx"

const order = makeAutoObservable({
    item: { name: "a" },
    replace(name) {
        this.item = { name }
    }
})

const log = []
autorun(() => {
    log.push(order.item.name)
})
const draft = { name: order.item.name }
draft.name = "c"
// log равен ["a"]
// order.item.name равен "a"

order.replace(draft.name)
// log равен ["a", "c"]
```

`draft` — другой объект. Запись в `draft.name` ни одну стрелку заказа не двигает. `replace` кладёт новое имя в ячейку `item`, и лог получает `"c"`. Имя текущего объекта меняйте через `order.item.name`. Другой объект показывайте через присваивание поля.

---

#### Сводка

| Жест | Кто читает `order.item.name` каждый проход | Кто держит прежний объект |
|---|---|---|
| Правка `item.name` | Видит новое имя | Видит новое имя, пока это тот же объект |
| Замена `item` | Видит объект, который лежит в ячейке теперь | Остаётся на прежнем объекте |

В обычной работе реакция каждый проход читает поле заказа. Ссылку на внутренний объект сохраняют только тогда, когда нужно и дальше смотреть именно на него.

#### Граница инструмента

Обе стрелки ведёт MobX. Присваивание поля и запись вложенного поля в JavaScript просто меняют данные. Кого из-за этого запустить снова, решает то, какие стрелки проход прочитал (этот уровень, п. 11).

#### Чем закрыть тему

Прочитайте `order.item.name` из `autorun` и поправьте `name` методом. Проверьте, что лог получил новое имя. Замените `item` другим объектом и проверьте, что лог увидел уже его имя. Сохраните объект в `const` до замены, читайте имя из этой переменной и проверьте, что после замены её лог не растёт.

Уровень base по оглавлению закончен.
