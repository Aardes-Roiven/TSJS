# Installing a dependency and the lockfile

Детализация п. 7 уровня «base», Node.js. Оглавление: [index.md](./index.md).

Конспект: сначала о чём речь и зачем это нужно на этом уровне, потом устройство, пример, ловушка и короткая формулировка, с которой тему можно закрыть.

#### О чём речь

Чужой пакет не появляется в программе оттого, что его имя написали в `import`. Его ставят командой `npm install` в каталоге, где лежит `package.json` проекта. Команда скачивает пакет в `node_modules`, записывает допустимый диапазон версий в `package.json` и записывает одну точную версию в `package-lock.json`. Без lockfile следующий `npm install` имеет право выбрать другую версию внутри диапазона. Программа, которая вчера запускалась, получает другой код.

---

#### Модель

`package.json` говорит, какие пакеты проекту нужны и в каком диапазоне. `package-lock.json` говорит, какое дерево реально поставили: точная версия каждого пакета, адрес и контрольная сумма `integrity`. `node_modules` — сами файлы на диске. Их восстанавливают установкой. В репозиторий кладут `package.json` и lockfile. Каталог `node_modules` туда не кладут: он большой и заново собирается из lockfile.

Команду запускают в корне проекта, рядом с его `package.json`. Установка в другом каталоге создаёт другой корень. Как по имени пакета находится папка в `node_modules` — этот уровень, п. 8.

---

#### npm install пишет три места сразу

`npm install left-pad` добавляет `left-pad` в `dependencies`. Значение — диапазон, обычно с `^`: внутри него допустим более новый совместимый выпуск. В `node_modules/left-pad` появляются файлы этой установки. В `package-lock.json` у `node_modules/left-pad` записаны конкретные `version` и `integrity`. Повторный `npm install` без аргументов ставит версии из lockfile, а не самую новую в диапазоне.

Пакет только для разработки и диапазоны версий — advanced, п. 30. Установка строго по lockfile и сбой, когда lockfile не сходится с `package.json`, — advanced, п. 31.

#### Lockfile фиксирует всё дерево

Прямая зависимость тянет свои пакеты. Lockfile записывает и их тоже, теми версиями, которые стояли в момент установки. Поэтому два компьютера с одним lockfile получают одно дерево. Диапазон в `package.json` сам по себе этого не обещает.

#### Правка node_modules не запоминается

Файл, изменённый внутри `node_modules`, пропадёт при следующей установке. Исправление версии делают новой установкой, чтобы изменились и `package.json`, и lockfile. Поле `overrides` для транзитивной зависимости — advanced, п. 32.

---

#### Пример

```text
npm install left-pad
```

После команды в `package.json` есть `dependencies.left-pad` с диапазоном. В `package-lock.json` у `node_modules/left-pad` одна точная `version` и поле `integrity`. Каталог `node_modules/left-pad` содержит файлы пакета. Импорт `left-pad` из файла этого проекта уже может найти пакет (этот уровень, п. 8).

---

#### Ловушка

Удалённый lockfile отпускает точные версии.

```text
rm package-lock.json
npm install
```

`npm install` заново выбирает версии внутри диапазонов из `package.json` и пишет новый lockfile. У `left-pad` и у пакетов, которые он тянет, в новом файле могут стоять другие `version`, чем в удалённом. Верните lockfile из репозитория и выполните `npm install` без его удаления: дерево снова совпадёт с записанным.

---

#### Сводка

| Место | Что в нём хранится |
|---|---|
| `package.json` → `dependencies` | Имя и допустимый диапазон |
| `package-lock.json` | Точная версия, адрес и `integrity` всего дерева |
| `node_modules` | Файлы последней установки, в репозиторий не входят |

В обычной работе пакет ставят через `npm install имя` в корне проекта и коммитят оба json-файла.

#### Граница инструмента

Это поведение `npm` и его `package-lock.json`. Сам Node пакеты из реестра не скачивает: он только читает уже лежащий `node_modules`, когда файл делает `import` или `require`.

#### Чем закрыть тему

Выполните `npm install left-pad` в каталоге с `package.json` и найдите диапазон в `dependencies`, точную `version` в lockfile и папку в `node_modules`. Удалите только `node_modules`, снова выполните `npm install` и проверьте, что `version` в lockfile не изменилась.
