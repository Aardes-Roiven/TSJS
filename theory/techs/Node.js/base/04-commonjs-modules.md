# CommonJS modules

Детализация п. 4 уровня «base», Node.js. Оглавление: [index.md](./index.md).

Конспект: сначала о чём речь и зачем это нужно на этом уровне, потом устройство, пример, ловушка и короткая формулировка, с которой тему можно закрыть.

#### О чём речь

CommonJS — второй формат модуля в Node. Файл отдаёт значение через `module.exports` и забирает его через `require`. Так до сих пор устроены многие пакеты и скрипты, у которых в `package.json` нет `"type": "module"`. Путаница одной пары имён ломает подключение: `exports = { add }` оставляет у вызывающего пустой объект, хотя функция в файле написана. Формат ECMAScript — этот уровень, п. 3. Какое расширение какой формат получает — advanced, п. 37.

---

#### Модель

`require("./math.js")` загружает файл, выполняет его и возвращает то, что файл записал в `module.exports`. Загрузка синхронная: следующая строка уже видит готовое значение. Повторный `require` того же файла не выполняет его заново и возвращает тот же объект. Сброс этого кэша — advanced, п. 64. Цикл, где два файла требуют друг друга, — advanced, п. 40.

У такого файла есть `__dirname` и `__filename` (этот уровень, п. 10). `import` и `export` в нём — синтаксическая ошибка, пока файл не переведён в модуль ECMAScript.

---

#### module.exports — это значение модуля

В начале файла `module.exports` — пустой объект. В него кладут поля: `module.exports.add = add`. Либо заменяют целиком: `module.exports = { add }`. Вызывающий получает именно это значение, в том числе функцию или число, если присвоили не объект.

#### exports — то же объект, пока переменную не заменили

Имя `exports` сначала указывает на тот же объект, что и `module.exports`. `exports.add = add` меняет этот объект, и `require` его видит. Присваивание `exports = { add }` отвязывает локальное имя. `module.exports` остаётся прежним пустым объектом. Наружу уходит он.

#### Путь require

`./math.js` — файл рядом. Для `.js`, `.json` и `.node` расширение в `require` можно опустить: `require("./math")` найдёт `math.js`. Каталог `require("./lib")` берёт `lib/index.js`, если это каталог. Имя без `./` ищется как пакет (этот уровень, п. 8) или как встроенный модуль (этот уровень, п. 5).

---

#### Пример

```javascript
function add(a, b) {
    return a + b
}

module.exports = { add }
```

```javascript
const { add } = require("./math.js")

console.log(add(2, 3))
// 5
```

`require` выполнил первый файл до конца и вернул объект с `add`. Вызов во втором файле получает `5`.

---

#### Ловушка

Замена переменной `exports` не меняет значение модуля.

```javascript
function add(a, b) {
    return a + b
}

exports = { add }
```

```javascript
const mod = require("./math.js")

console.log(mod)
// {}
console.log(typeof mod.add)
// undefined
```

Функция `add` есть только в локальной переменной первого файла. Вызывающий получил пустой `module.exports`. Запись, которая отдаёт объект наружу: `module.exports = { add }`. Добавить поле к уже существующему объекту можно и через `exports.add = add`.

---

#### Сводка

| Запись в файле | Что возвращает require |
|---|---|
| `module.exports = { add }` | Объект с полем `add` |
| `exports.add = add` | Тот же объект с полем `add` |
| `exports = { add }` | Пустой объект, поля `add` нет |

В обычной работе значение модуля записывают в `module.exports`. `exports.поле` используют, только чтобы добавить поле к этому объекту.

#### Граница инструмента

`require` и `module` добавляет Node, когда файл загружен как CommonJS. В модуле ECMAScript этих имён нет: `require` там `ReferenceError`. Подключить модуль ECMAScript через `require` — advanced, п. 39.

#### Чем закрыть тему

Отдайте объект через `module.exports` и проверьте, что `require` вызывает функцию из него. Замените присваивание на `exports = { ... }` и проверьте, что `require` вернул пустой объект без этой функции.
