# Built-in modules and the node: scheme

Детализация п. 5 уровня «base», Node.js. Оглавление: [index.md](./index.md).

Конспект: сначала о чём речь и зачем это нужно на этом уровне, потом устройство, пример, ловушка и короткая формулировка, с которой тему можно закрыть.

#### О чём речь

Часть возможностей Node уже лежит в самом процессе: пути, файлы, сеть, процесс. Их не ставят через `npm`. Имя такого модуля пишут со схемой `node:`, например `node:path` и `node:fs`. Без схемы часть старых имён тоже открывается, и из-за этого легко решить, что схема необязательна всегда. Модуль `node:test` без приставки ищется как пакет и не находится. Свой файл `path.js` рядом со скриптом имя `"path"` тоже не выбирает.

---

#### Модель

Встроенный модуль — это код, который поставляется вместе с `node`, а не папка в `node_modules`. Схема `node:` прямо называет этот источник. Дальше идёт имя модуля и иногда подпуть: `node:fs/promises` — обещания для файлов, ими пользуются в этот уровень, п. 12.

Имя без `node:` и без `./` Node сначала сверяет со списком давних встроенных модулей. `fs`, `path` и `http` находятся там. Имени в этом списке нет — поиск идёт в `node_modules` (этот уровень, п. 8). Схема `node:` этот обход не делает: либо встроенный модуль, либо ошибка.

---

#### Схема называет модуль однозначно

`import path from "node:path"` и `const path = require("node:path")` дают один и тот же встроенный модуль. `path.join` — функция. Пакет с таким именем из `node_modules` при схеме `node:` не подменяет модуль. Для нового кода имя пишут со схемой.

#### Старое короткое имя покрывает не весь список

`require("path")` и `import path from "node:path"` для `path` совпадают: оба дают встроенный модуль. `import "test"` ищет пакет `test` и падает с `ERR_MODULE_NOT_FOUND`: `Cannot find package 'test'`. Рабочая запись — `import test from "node:test"`. То же правило у других модулей, которые появились уже со схемой.

#### Свой файл берут относительным путём

Файл `path.js` рядом со скриптом открывают как `./path.js`. Запись `"path"` или `"node:path"` на него не смотрит. Относительный импорт — этот уровень, п. 3 и п. 4.

---

#### Пример

```javascript
import path from "node:path"

console.log(typeof path.join)
// function
```

`node:path` загрузился из установки Node. Пакета `path` в проекте для этого нет. `path.join` дальше собирает путь к файлу (этот уровень, п. 11).

---

#### Ловушка

Локальный `path.js` не перехватывает имя встроенного модуля.

```javascript
module.exports = { local: true }
```

Файл называется `path.js` и лежит рядом с программой.

```javascript
const path = require("path")

console.log("join" in path)
// true
console.log(path.local)
// undefined
```

`require("path")` вернул встроенный модуль. Поля `local` в нём нет. Свой файл подключают через `require("./path.js")`.

---

#### Сводка

| Запись | Откуда модуль |
|---|---|
| `node:path`, `node:fs`, `node:fs/promises` | Встроенный модуль Node |
| `path`, `fs`, `http` без схемы | Тот же встроенный модуль, старое имя |
| `node:test` | Встроенный модуль, только со схемой |
| `test` без схемы | Поиск пакета, для встроенного модуля это ошибка |
| `./path.js` | Файл рядом со скриптом |

В обычной работе встроенное имя пишут как `node:...`. Свой файл начинают с `./`.

#### Граница инструмента

Список встроенных модулей принадлежит версии Node. Имя, которого нет в этой версии, со схемой `node:` даёт ошибку загрузки, а не тихий запасной файл из проекта.

#### Чем закрыть тему

Импортируйте `node:path` и проверьте, что `path.join` — функция. Положите рядом свой `path.js` с другим полем, подключите `"path"` и проверьте, что этого поля нет. Подключите `./path.js` и проверьте, что поле появилось.
