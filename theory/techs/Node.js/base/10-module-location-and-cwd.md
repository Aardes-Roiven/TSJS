# The current module location and the working directory

Детализация п. 10 уровня «base», Node.js. Оглавление: [index.md](./index.md).

Конспект: сначала о чём речь и зачем это нужно на этом уровне, потом устройство, пример, ловушка и короткая формулировка, с которой тему можно закрыть.

#### О чём речь

У процесса два разных каталога. Каталог модуля — папка, в которой лежит файл, выполняемый сейчас. Рабочий каталог — папка, из которой запустили `node`. Относительный путь к данным, собранный от рабочего каталога, при запуске из другого места указывает на другой файл. Путь, собранный от каталога модуля, остаётся рядом с программой. Путаница этих двух папок — обычная причина «файл есть, а программа его не видит».

---

#### Модель

Рабочий каталог хранит `process.cwd()`. Его задаёт shell в момент запуска и его меняет `process.chdir`. Каталог модуля от этого не двигается: файл программы остаётся на своём месте.

В модуле ECMAScript каталог файла — `import.meta.dirname`, полный путь к файлу — `import.meta.filename`. В CommonJS те же смыслы у `__dirname` и `__filename`. Как из этих частей собрать путь с `..` и абсолютными кусками — этот уровень, п. 11. Как прочитать сам файл — этот уровень, п. 12.

---

#### Каталог модуля не зависит от места запуска

`import.meta.dirname` в модуле ECMAScript — абсолютный путь к папке этого файла. Запуск `node /proj/sub/app.js` из `/` оставляет dirname равным `/proj/sub`. В CommonJS то же даёт `__dirname`. Имени `__dirname` в модуле ECMAScript нет: обращение к нему — `ReferenceError`.

Файл данных рядом с программой собирают от этого каталога. Тогда запуск из другого места продолжает видеть тот же файл.

#### Рабочий каталог — место запуска

`process.cwd()` возвращает папку запуска. `path.resolve("data.txt")` и голое относительное имя в вызове чтения файла опираются на неё. Запуск из `/` ищет `/data.txt`. Запуск из `/proj` ищет `/proj/data.txt`. Программа та же.

`process.chdir("/tmp")` меняет дальнейшие `process.cwd()` и дальнейшие относительные пути. Уже посчитанный путь к каталогу модуля не меняется.

---

#### Пример

Файл `sub/where.mjs`:

```javascript
import path from "node:path"

console.log(import.meta.dirname)
console.log(process.cwd())
console.log(path.join(import.meta.dirname, "data.txt"))
```

Команда `node sub/where.mjs` из родителя `sub` печатает каталог `.../sub`, затем каталог родителя, затем `.../sub/data.txt`. Файл `data.txt` привязан к модулю, хотя команда набрана на этаж выше.

---

#### Ловушка

Путь без каталога модуля следует за местом запуска.

```javascript
import path from "node:path"

console.log(import.meta.dirname)
console.log(path.resolve("data.txt"))
```

Тот же `sub/where.mjs`, команда из корня диска: `node /полный/путь/sub/where.mjs`. Первая строка по-прежнему каталог `sub`. Вторая — `/data.txt`. Рядом с программой этого файла нет. Данные программы собирайте от `import.meta.dirname` или от `__dirname`. Правила `path.resolve` — этот уровень, п. 11.

---

#### Сводка

| Вопрос | Модуль ECMAScript | CommonJS |
|---|---|---|
| Папка этого файла | `import.meta.dirname` | `__dirname` |
| Путь к этому файлу | `import.meta.filename` | `__filename` |
| Папка запуска | `process.cwd()` | `process.cwd()` |

В обычной работе файлы, которые лежат вместе с программой, собирают от каталога модуля. Путь, который пользователь передал аргументом, оставляют как есть: его толкование относительно запуска — уже дело этого аргумента.

#### Граница инструмента

`process.cwd()` — свойство процесса в операционной системе. `import.meta.dirname` добавляет Node к модулю ECMAScript. В CommonJS его нет, там своё имя `__dirname`.

#### Чем закрыть тему

Напечатайте `import.meta.dirname` и `process.cwd()` из файла во вложенной папке. Запустите его из родителя и из корня диска. Проверьте, что каталог модуля совпал оба раза, а `path.resolve("data.txt")` сменился вместе с местом запуска.
