# ECMAScript modules

Детализация п. 3 уровня «base», Node.js. Оглавление: [index.md](./index.md).

Конспект: сначала о чём речь и зачем это нужно на этом уровне, потом устройство, пример, ловушка и короткая формулировка, с которой тему можно закрыть.

#### О чём речь

Модуль ECMAScript — это файл, который отдаёт наружу имена через `export` и забирает чужие через `import`. Так одна программа делится на файлы, и каждый файл видит только то, что у него попросили. В Node такой файл обязан быть помечен: расширение `.mjs` или `"type": "module"` в `package.json` (этот уровень, п. 6). Относительный импорт без расширения файла не находит соседний `.js`. Импорт имени, которого файл не экспортировал, падает до выполнения тела.

---

#### Модель

Каждый модуль выполняется один раз. Повторный импорт того же файла получает уже созданные экспорты, а не новый запуск. `import` связывает имя с экспортом другого файла. Это не копия, снятая в момент импорта: чтение имени видит текущий экспорт.

Импорт ищется и связывается до тела модуля. Относительный путь начинается с `./` или `../` и включает расширение. Имя без точки — пакет из `node_modules` (этот уровень, п. 8) или встроенный модуль (этот уровень, п. 5).

---

#### Именной экспорт и экспорт по умолчанию

`export function add` отдаёт имя `add`. Забирают его так: `import { add } from "./add.js"`. `export default` отдаёт значение без имени. Забирают его так: `import add from "./add.js"`. Фигурные скобки ищут имя. Запись без скобок ищет экспорт по умолчанию. В одном файле может быть один экспорт по умолчанию и сколько угодно именных.

#### Относительный путь включает расширение

`./add.js` — соседний файл. `./add` — другой адрес. Node не подставляет `.js` сам и сообщает `ERR_MODULE_NOT_FOUND`. В тексте ошибки есть подсказка вида `Did you mean to import "./add.js"?`. Каталог `./lib` тоже не выбирает `index.js` сам: путь пишут до файла.

#### В модуле нет require и __dirname

`require` в таком файле не определён. Модули CommonJS подключают иначе (этот уровень, п. 4; вызов CommonJS из модуля ECMAScript — advanced, п. 38). Каталог текущего файла берут из `import.meta.dirname` (этот уровень, п. 10).

---

#### Пример

```javascript
export function add(a, b) {
    return a + b
}
```

```javascript
import { add } from "./add.js"

console.log(add(2, 3))
// 5
```

Второй файл забирает имя `add` из первого. Сложения в первом файле нет, пока второй не вызвал функцию. Оба файла — модули: `.mjs` либо `"type": "module"`.

---

#### Ловушка

Импорт без фигурных скобок ищет экспорт по умолчанию.

```javascript
export function add(a, b) {
    return a + b
}
```

```javascript
import add from "./add.js"

console.log(add(2, 3))
```

Запуск падает с `SyntaxError: The requested module './add.js' does not provide an export named 'default'`. Функция `add` в файле есть, но она отдана по имени. Импорт пишут как `import { add } from "./add.js"`.

---

#### Сводка

| Запись в файле-источнике | Запись у того, кто импортирует |
|---|---|
| `export function add` | `import { add } from "./add.js"` |
| `export default function add` | `import add from "./add.js"` |
| путь `./add` | `ERR_MODULE_NOT_FOUND`, нужен `./add.js` |

В обычной работе у относительного импорта есть `./` и расширение, а скобки вокруг имени совпадают со способом экспорта.

#### Граница инструмента

Это правило загрузчика модулей Node. Браузер тоже требует расширение в относительном импорте. Сборка, которая понимает `./add` без `.js`, делает это своим шагом до Node. Полная встреча расширения и поля `type` — advanced, п. 37.

#### Чем закрыть тему

Экспортируйте функцию по имени, импортируйте её через `./файл.js` и проверьте результат вызова. Уберите расширение и проверьте `ERR_MODULE_NOT_FOUND`. Импортируйте ту же функцию без фигурных скобок и проверьте ошибку про отсутствующий `default`.
