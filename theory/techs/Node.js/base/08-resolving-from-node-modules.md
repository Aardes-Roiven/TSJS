# Resolving a package from node_modules

Детализация п. 8 уровня «base», Node.js. Оглавление: [index.md](./index.md).

Конспект: сначала о чём речь и зачем это нужно на этом уровне, потом устройство, пример, ловушка и короткая формулировка, с которой тему можно закрыть.

#### О чём речь

Имя пакета в `import` или `require` — не путь на диске. Node ищет папку `node_modules` вверх от файла, который это имя написал, и берёт пакет оттуда. Поиск начинается у файла, а не у каталога, из которого вы набрали команду `node`. Скрипт, лежащий вне проекта, не видит пакеты этого проекта, даже если команду запустили из корня. Как пакет туда попал — этот уровень, п. 7.

---

#### Модель

Строка без `./`, без `../` и без схемы `node:` — имя пакета. У файла `proj/app.js` Node смотрит `proj/node_modules/<имя>`. Папки нет — поднимается к родителю и смотрит ещё раз, до корня диска. Первая найденная папка выигрывает. Вложенный `node_modules` ближе к файлу перекрывает пакет у корня репозитория.

Найденная папка — ещё не файл с кодом. Дальше Node открывает вход пакета. Карта `exports` выбирает файл по правилам advanced, п. 33. Если карты нет, вход — поле `main` в `package.json` пакета, а без `main` — `index.js`.

---

#### Имя пакета и относительный путь — разный поиск

`require("leftpad")` ищет пакет. `require("./leftpad.js")` открывает файл рядом и в `node_modules` не заходит. `require("./node_modules/leftpad/index.js")` тоже открывает файл по пути и обходит вход пакета. В программе пишут голое имя, чтобы сработал поиск.

#### Рабочий каталог в поиске не участвует

`process.cwd()` может быть корнем проекта, а файл скрипта — в `/tmp`. Поиск идёт от каталога этого скрипта. Пакеты, установленные в проекте, ему не видны. Каталог модуля и рабочий каталог — этот уровень, п. 10.

#### Две копии одного имени

Если и у корня, и рядом с файлом есть свой `node_modules/leftpad`, файл видит ближайшую папку. Это другой экземпляр пакета, со своей версией. Две физические копии одного пакета в дереве — expert, п. 69.

---

#### Пример

Рядом с программой лежит мини-пакет:

```text
app.js
node_modules/leftpad/package.json
node_modules/leftpad/index.js
```

```json
{ "name": "leftpad", "main": "index.js" }
```

```javascript
module.exports = (text) => "LP:" + text
```

```javascript
console.log(require("leftpad")("x"))
// LP:x
```

`require("leftpad")` нашёл `node_modules/leftpad` в каталоге `app.js`, прочитал `main` и выполнил `index.js`. Префикс `LP:` пришёл из пакета, не из `app.js`.

---

#### Ловушка

Скрипт вне дерева пакета не видит его `node_modules`.

```javascript
console.log(require("leftpad")("x"))
```

Файл лежит в `/tmp/outside/app.js`. Пакет установлен только в `proj/node_modules/leftpad`. Команда из корня проекта:

```text
node /tmp/outside/app.js
```

Запуск падает: `Cannot find module 'leftpad'`. Поиск начался в `/tmp/outside` и поднялся к корню диска, не заходя в `proj`. Перенесите скрипт в `proj`, чтобы его каталог был тем же деревом, что и `node_modules`.

---

#### Сводка

| Запись | Где ищет Node |
|---|---|
| `leftpad` | `node_modules/leftpad` вверх от файла скрипта |
| `node:path` | Встроенный модуль, не `node_modules` |
| `./leftpad.js` | Файл относительно скрипта |
| тот же `leftpad` из файла вне проекта | Дерево того файла, не каталог запуска |

В обычной работе программа живёт внутри проекта, а пакет подключают голым именем.

#### Граница инструмента

Поиск делает загрузчик Node в момент `import` или `require`. `npm` к этому моменту уже закончил работу: он только положил папки на диск.

#### Чем закрыть тему

Положите маленький пакет в `node_modules` рядом со скриптом и проверьте, что голое имя вызывает его функцию. Запустите файл из каталога вне этого дерева той же командой `node` с абсолютным путём и проверьте `Cannot find module`.
