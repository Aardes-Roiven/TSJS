# Running a script with node

Детализация п. 1 уровня «base», Node.js. Оглавление: [index.md](./index.md).

Конспект: сначала о чём речь и зачем это нужно на этом уровне, потом устройство, пример, ловушка и короткая формулировка, с которой тему можно закрыть.

#### О чём речь

Файл с программой сам не выполняется. Его запускает программа `node`, и операционная система заводит для этого отдельный процесс. Команда `node hello.js` читает один файл сверху вниз, печатает то, что попросили, и завершается, когда делать больше нечего. Без явного файла `node` открывает интерактивную консоль и ждёт ввод. Флаги самого `node` пишут до имени файла. То, что стоит после имени, программа уже читает как свои аргументы (этот уровень, п. 9).

---

#### Модель

`node` — обычная программа, установленная в системе. Аргумент — путь к файлу, который станет входом. Этот файл выполняется один раз за запуск. Состояние прошлого запуска не сохраняется: следующий `node hello.js` снова начинает с первой строки. Другие файлы подключаются, только если вход их импортирует (этот уровень, п. 3 и п. 4).

Когда код файла дошёл до конца и не осталось таймера, сервера или другой открытой ручки, процесс завершается. Что именно держит процесс живым — этот уровень, п. 18. Число, с которым процесс расстаётся с операционной системой, — этот уровень, п. 2.

---

#### Имя файла — это вход

`node hello.js` выполняет `hello.js` из текущего каталога. Путь может быть и вложенным: `node src/hello.js`. Команда `node` без пути к файлу вход не выбирает: она читает строки, которые вы наберёте дальше. Короткую программу без файла запускают так: `node -e "console.log(1)"`.

#### Флаги node стоят перед именем файла

`node --inspect hello.js` включает отладчик и затем выполняет файл. Те же символы после имени файла отладчик не включают. Их забирает сама программа: список `process.argv`. Флаги, которые прочитал `node`, лежат отдельно, в `process.execArgv`.

#### Файл выполняется сверху вниз

Строки идут по порядку. Исключение обрывает оставшиеся строки, и процесс заканчивается с кодом 1 (этот уровень, п. 2). Повторный запуск снова выполняет файл с начала.

---

#### Пример

```javascript
console.log("hello")
```

Команда `node hello.js` печатает `hello` и сразу завершает процесс. Второго запуска внутри той же команды нет.

---

#### Ловушка

Флаг после имени файла не достаётся `node`.

```javascript
console.log(process.execArgv)
console.log(process.argv.slice(2))
```

Команда `node app.js --inspect` печатает `[]`, затем `["--inspect"]`. Отладчик молчит. `--inspect` попал в аргументы скрипта. Команда `node --inspect app.js` включает отладчик: флаг оказывается в `process.execArgv`, а хвост `argv` пуст.

---

#### Сводка

| Команда | Кто читает хвост |
|---|---|
| `node hello.js` | Выполняется `hello.js`, хвоста нет |
| `node` | Консоль ждёт ввод, файл не выбран |
| `node --inspect hello.js` | Флаг читает `node`, затем выполняется файл |
| `node hello.js --inspect` | Файл выполняется, `--inspect` видит программа |

В обычной работе файл называют явно, а флаги `node` ставят перед этим именем.

#### Граница инструмента

Запуск делает операционная система: она создаёт процесс и потом забирает код выхода. Строка `#!/usr/bin/env node` в первой строке файла нужна, когда файл запускают как программу системы, без явного `node` в команде.

#### Чем закрыть тему

Запустите файл командой `node hello.js` и проверьте, что строка напечаталась, а процесс закончился. Повторите запуск с `--inspect` после имени файла и проверьте, что флаг лежит в `process.argv`. Перенесите флаг перед именем и проверьте, что он попал в `process.execArgv`.
