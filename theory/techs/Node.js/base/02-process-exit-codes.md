# Process exit codes

Детализация п. 2 уровня «base», Node.js. Оглавление: [index.md](./index.md).

Конспект: сначала о чём речь и зачем это нужно на этом уровне, потом устройство, пример, ловушка и короткая формулировка, с которой тему можно закрыть.

#### О чём речь

Когда процесс заканчивается, он оставляет операционной системе целое число. Ноль значит, что работа прошла как задумано. Любое другое число значит сбой. Скрипт, `npm` и соседняя команда в shell смотрят на это число, а не на текст в терминале. `console.error("failed")` печатает красную строку и всё равно завершает процесс с нулём, если код не задать. Вызывающая сторона считает запуск успешным.

---

#### Модель

Код выхода — это записка на двери, а не сообщение внутри комнаты. Текст в stdout и stderr человек может прочитать. Число читает следующая программа. Обычное завершение файла оставляет 0. Необработанное исключение оставляет 1: оставшиеся строки файла уже не выполняются. Как устроены необработанные исключения и отклонённые промисы — этот уровень, п. 19.

Код — целое от 0 до 255. Учитываются младшие 8 бит, поэтому 256 превращается в 0.

---

#### process.exitCode оставляет число и не обрывает файл

Присваивание `process.exitCode = 1` запоминает код. Строки после него всё ещё выполняются. Когда файл дошёл до конца и процесс больше ничто не держит (этот уровень, п. 18), `node` отдаёт операционной системе это число. Так сообщают о сбое и успевают дописать лог.

#### process.exit заканчивает процесс сразу

`process.exit(1)` тут же завершает процесс с кодом 1. Строки ниже этого вызова не выполняются. Аргумент заменяет ранее записанный `process.exitCode`. Вызов без аргумента отдаёт уже записанный код, а если его не было — 0. События вокруг самого выхода — expert, п. 29. Код после смертельного сигнала — expert, п. 28.

#### Напечатанная ошибка код не меняет

`console.error` пишет в stderr. Код выхода остаётся 0, пока его не задали и пока не было необработанного исключения. Проверка в bash — `echo $?` сразу после команды.

---

#### Пример

```javascript
console.error("failed")
process.exitCode = 1
console.log("cleanup")
```

Команда `node app.js` печатает `failed`, затем `cleanup`. В bash `echo $?` показывает `1`. Чистка успела выполниться, а для shell запуск всё равно неуспешный.

---

#### Ловушка

Сообщение об ошибке без кода выглядит как сбой только человеку.

```javascript
console.error("failed")
```

`node app.js` печатает `failed`. `echo $?` показывает `0`. Следующая команда в цепочке `&&` выполняется. Задайте `process.exitCode = 1` до конца файла, если этот запуск надо считать неуспешным.

---

#### Сводка

| Как заканчивается процесс | Код | Строки после места сбоя |
|---|---|---|
| Файл дошёл до конца | 0 | Уже выполнены |
| `process.exitCode = 1`, файл дошёл до конца | 1 | Выполняются |
| `process.exit(1)` | 1 | Не выполняются |
| Необработанное исключение | 1 | Не выполняются |
| Только `console.error` | 0 | Выполняются |

В обычной работе сбой — это ненулевой `process.exitCode`. `process.exit` берут, когда процесс нужно оборвать немедленно.

#### Граница инструмента

Число читает операционная система и shell. Node его только передаёт. TypeScript это число не проверяет: код 0 при напечатанной ошибке остаётся поведением процесса.

#### Чем закрыть тему

Завершите файл с `process.exitCode = 1` и проверьте, что строка после присваивания напечаталась, а `echo $?` показывает `1`. Уберите присваивание, оставьте `console.error`, и проверьте, что `echo $?` показывает `0`.
